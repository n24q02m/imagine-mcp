## 2026-07-28 - Consolidate thread-pool dispatches for concurrent I/O operations inside request handlers
**Learning:** In the `status` handler of the MCP `config` tool, three distinct properties (`version`, `credentials_state`, and `providers_configured`) were each firing off their own `asyncio.to_thread` call, with `credentials_state` redundantly calling `_providers_configured_live` a second time. This led to multiple thread allocations and redundant file decryptions from `PerPluginStore`.
**Action:** When a request handler aggregates multiple synchronous I/O or CPU operations to produce its response, bundle those operations into a single synchronous helper function and execute that helper in one `asyncio.to_thread` call. Unpack the resulting dictionary to serve the final response, minimizing thread-pool and context-switching overhead while avoiding duplicate work.
